## 1. Fresh clone to first useful screen

Followed the `README.md` "Getting Started" section exactly, in a temp dir, as a visitor with no Alpaca or OpenRouter keys. The server was bound to 127.0.0.1:8811 (never 8791) and stopped afterwards.

| Sign in | — | The token is in terminal scrollback or `.env` (see S3) |
| Setup wizard, step 1 (LLM key) | — | Blocked without a key. "Skip for now" works. |

**Before this branch, a visitor without keys never reached a useful screen.** With keys, the path also needs an OpenRouter or Anthropic account with credit plus an Alpaca paper account. I did not create accounts, so I did not time that part; a fair estimate is 5–15 minutes, most of it outside the app.

**After this branch** (the README's three commands, run from a fresh clone of this branch, empty uv cache, no `uv sync`):

```
git clone … && cd allpath-trading-agent && uv run allpath-trade demo
```

Clone to a populated, signed-in UI took **14.2 s**. The clone stayed clean: the demo writes only to its temp dir.

## 2. Demo mode (built on this branch)

`uv run allpath-trade demo [--dir PATH] [--host 127.0.0.1] [--port 8790]`

What a visitor sees:
- Dashboard: $101.7k equity, NVDA and AAPL positions, a synthetic 200-day equity curve.
- Strategies: three YAML strategies: active `confirm`, active `notify`, and a draft.
- Pending: a triggered NVDA buy with the agent's analysis and Approve/Reject buttons, plus a reflection-proposed stop revision shown as a diff. Both can be approved: the order fills (simulated) and the revision rewrites the demo's own YAML file.
- Reports: one nightly report. Memory: one entry in each layer.
- A "Demo mode — sample data and simulated fills; nothing reaches a broker" banner on every page.

Safety properties, each covered by `tests/test_demo.py` (28 tests):
- It runs in its own working directory (a new temp dir by default) and `chdir`s there before loading settings, so `.env`, the DB, `strategies/` and `memory/` of the starting directory are never read or written. A test starts the demo from a directory with a "real" `.env` and checks it is untouched.
- `main()` dispatches `demo` before any settings load. A test uses an invalid local `.env` that every other command rejects.
- Paper's broker is `DemoBroker`: static positions, fills kept in memory. Quotes come from `DemoData`: fixed sample prices, no network.
- No scheduler. Before anything is built, every outbound credential (`ALPACA_*`, `TELEGRAM_BOT_TOKEN`, `SMTP_*`, `NOTIFY_TO`, `NTFY_URL`, `AGENT_WEBHOOK_*`, `PUBLISH_*`, `WEB_BASE_URL`, `WEB_TOKEN`) is removed from the process environment, so no Telegram poller can start. LLM keys are deliberately kept: with one, chat works against the sandboxed data.
- Production wiring changes are two optional keyword arguments, `build_components(..., data=None)` and `create_app(..., builder=None)`, plus a `demo_mode` flag in `nav_context` that is true only when the broker is named `demo`. Defaults are unchanged; the full suite passes (2964).

Known limits and next steps:
- Without an LLM key the chat page shows the usual "add a key" notice. **Next step:** a scripted stub LLM that replays one canned conversation (ask about NVDA → research → draft → proposal card), so the core "talk to it" promise is demoable with no key. This is roughly another 150 lines plus tests, because `ChatService` builds a real tool loop.
- The shadow account is empty in the demo.
- Sample prices are fixed. Strategy cards show a fixed daily change.
